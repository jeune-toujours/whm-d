# WHM D

Клиентский Svelte frontend и Payload backend для WHM. Staging работает через WHM API с PostgreSQL/S3 в Selectel. SMS и платежи симулируются; все данные тестовые. Инструкция по первой рабочей версии: [`docs/staging-product-v1.md`](docs/staging-product-v1.md).

Текущий этап сосредоточен на структуре и логике. Существующая UI-система сохранена и приведена к единому виду: Open Sans, жёлтая акцентная палитра, общие размеры, карточки, состояния и светлая/тёмная темы. Логотип, фирменные изображения и декоративные иллюстрации удалены; медиа-зоны показывают нейтральные плейсхолдеры. Все интерфейсные иконки берутся только из бесплатного набора `@lucide/svelte`.

**Основной dev-домен:** https://whm.pikman.studio

**Staging:** https://test-whm.pikman.studio (`develop`)

**GitHub:** https://github.com/jeune-toujours/whm-d (публичный репозиторий).

Архитектура и backend: [`docs/backend.md`](docs/backend.md). Релизы через VM/Coolify: [`docs/releases.md`](docs/releases.md).

## Запуск

Требуется Node.js 24 или совместимая версия.

```bash
npm ci
npm run dev
```

Откройте адрес Vite из терминала. Для сборки и проверки:

```bash
npm run build
npm run test:flows
```

Браузерные проверки используют установленный Google Chrome. При другом пути задайте `CHROME_PATH`. Чтобы проверить опубликованный контур, задайте `WHM_BASE_URL`.

## Просмотр

- `/#/home` — главный экран клиента.
- `/#/preview` — карта всех клиентских экранов, переключение сценариев «с вещами» / «первый вход» и этапов активного заказа.
- Верхняя панель «Все экраны» доступна на любом экране.
- Созданные в демо заказы, обращения и изменения профиля сохраняются только в `localStorage` текущего браузера. Переключение сценария сбрасывает демо-данные.

Любой четырёхзначный код, кроме `0000`, проходит демонстрационную проверку OTP. SMS не отправляется. Оплата и привязка карты имитируются без ввода реквизитов и списаний.

## Устройство и границы

Восемь исходных автономных экранов Svelte 5 подключены через [`src/App.svelte`](src/App.svelte). Карточка вещи, управление подпиской, история платежей и карта просмотра добавлены в `src/screens`. Общие демо-данные и операции находятся в [`src/demo.js`](src/demo.js). Маршруты используют hash URL, поэтому статическая сборка работает на Vercel без серверных rewrite-правил.

Описание решений, источников и следующего этапа: [`docs/client-preview.md`](docs/client-preview.md).

## Публикация

Текущий способ публикации — GitHub App → Coolify на VM. `develop` публикует staging, `main` — основной контур. Перед merge выполнить проверки и дождаться CI; после deployment проверить HTTPS и SHA релиза. Команды и ограничения описаны в [`docs/releases.md`](docs/releases.md).

Vercel-конфигурация и прежний документ `docs/client-preview.md` относятся к историческому демо-превью.
