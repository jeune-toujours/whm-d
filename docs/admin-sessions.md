# Сессии клиента и сотрудников · v0.1.3

## Причина раннего выхода из Admin

В v0.1.2 клиентский OTP и Payload Admin записывали одну `payload-token` cookie на общем домене с `Path=/`. Воспроизведено на staging: сотрудник входит → клиент входит в том же браузере → `/api/users/me` возвращает `client` вместо `admin`; выход клиента удаляет общую cookie. Это происходило независимо от времени: фактический TTL staff JWT и cookie уже составлял 604800 секунд (7 дней). localStorage содержит UI-настройки, не auth token.

## Исправление

- Нативная `payload-token` остаётся для Payload Admin. Существующие действующие сессии сотрудников сохраняются.
- Клиент использует отдельную HttpOnly `whm-client-token`, с теми же Secure/SameSite/expiry настройками Payload.
- На REST-границе `auth-context.ts` выбирает cookie для клиентского запроса и передаёт её штатному Payload JWT/session validator. Ответные auth cookies переименовываются только в клиентском контексте. При отсутствии клиентской cookie staff-cookie не используется как fallback.
- `/api/auth/*` и `/api/me` всегда клиентские. Остальные Svelte API-запросы, включая upload, маркируются `X-WHM-Client: 1`; скачивание квитанции — `?whm-client=1`, поскольку window.open не устанавливает custom headers. Маркер выбирает сессию, но не даёт никаких прав.
- Нативные Admin routes, server actions, refresh и logout используют staff-cookie без изменений. Включён штатный `admin.autoRefresh`.
- Семидневный TTL, проверка серверного SID, роли/ownership, CSRF и Secure/HttpOnly сохраняются. Токены не переносятся в localStorage. Схема БД не меняется; миграция не нужна.

После обновления перезагрузите открытые клиентские вкладки: старый frontend не знает новый cookie context. Клиентам со старой общей cookie потребуется один вход по OTP. Уже перезаписанную старым клиентом staff-сессию нужно восстановить входом сотрудника.

## Проверка

1. В одном профиле браузера войти в Admin и открыть приёмку.
2. В другой вкладке того же профиля пройти клиентский OTP, оформить заявку, обновить клиентский кабинет и Admin.
3. Обе вкладки сохраняют свою роль. Клиентская загрузка и квитанции используют клиентскую сессию.
4. Выйти из клиента: Admin остаётся доступен. Выйти из Admin: клиент остаётся доступен.
5. Проверить отдельное обновление обоих токенов, отсутствие fallback после client logout и серверный отзыв SID. Сотрудник без клиентского входа получает 401 на `/api/me`.

Автотесты: `backend/tests/auth-context.test.ts`, `session-isolation.integration.ts`, обновлённые auth/workflows integration tests и `npm run test:live`. Live smoke теперь выполняет весь клиентский и складской процесс в одном browser context, включая client logout и последующий reload рабочего экрана. Production/main этим исправлением не меняются.
