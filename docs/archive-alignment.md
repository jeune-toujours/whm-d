Существующие темы, Open Sans, карточки, отступы и Lucide сохранены. Все декоративные изображения остаются нейтральными плейсхолдерами. В live-сценарии нет встроенных карт.

Черновики форм хранятся в `sessionStorage`, отдельно по серверному ID клиента; после успеха удаляются. Это временные введённые данные формы, а не локальная база заказов. `localStorage` используется только для темы. Ключ повторной операции сохраняется в черновике и зависит от состава запроса.

## Серверные границы

WHM API рассчитывает тестовые цены из активного каталога, проверяет услуги, согласие, собственника, статус вещи, блокировку и участие в незавершённой сдаче. Цена браузера не принимается. Quote hash защищает от изменения расчёта до оплаты. Транзакции и PostgreSQL advisory locks защищают оплату, резервирование и повторные запросы. История берёт названия, цены и логистику из снимка операции; последующее переименование вещи не меняет снимок.

Адреса, зона доставки, интервалы и цены логистики — явные тестовые fixtures из архива, а не подключение реального планировщика. Тестовый расчёт включает первый месяц, услуги, доставку и выбранную симуляцию страхования. Реальные повторные начисления и коммерческая политика не утверждены и не выполняются.

Миграции `20261004_185503_20261004_archive_alignment` и `20261004_191637_20261004_support_alignment` добавляют поля без сброса базы. Для старых записей восстанавливается дата закрытия и поисковый текст; интерфейс честно предупреждает об отсутствии исходного снимка. Миграции вниз не запускаются автоматически: они удаляют новые поля и требуют отдельного решения.

## Пробелы исходных требований

- WHM-5: карточка содержит ошибочное вложение WHM-7; WHM-14: карточка без сценария. Использованы существующие клиентские экраны; полное соответствие отсутствующему макету подтвердить невозможно.
- Коммерческие тарифы, регулярный биллинг, страховые условия, документы, SLA поддержки, физическая доступность слотов и внешние SMS/payment/email/MySklad остаются неподключёнными. Симуляция не подтверждает реальные услуги.
- В WHM-13 есть противоречие: общий запрет понижения с вещами и критерий запрета только при превышении лимита. Используется проверяемый критерий лимита; решение о более строгом запрете требуется отдельно.

## Проверка и выпуск

Обязательны frontend check/build/test:flows, backend check/unit/build и CI на PostgreSQL с приватным тестовым S3. Проверяется весь архивный клиентский путь сдача → оплата с отказом и повтором → приёмка/размещение → возврат → подбор/выдача с фото и подписью → история. Production не входит в этот выпуск.

Релиз считается опубликованным только после зелёного CI, `finished` в Coolify, healthy приложений, совпадения commit SHA на `/release.json` и `/api/health`, `/api/ready` и браузерной проверки staging. Итог фиксируется в `docs/releases.md` и плане сверки в Notion.
