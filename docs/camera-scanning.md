# WHM MVP v0.1.2: сканирование штрихкодов камерой

## Работа сотрудника

В приёмке, размещении и подборе рядом с «Скан вещи» появилась кнопка камеры Lucide; в размещении также рядом с «Скан ячейки».

1. Нажать камеру, разрешить браузеру доступ и навести на один код целиком.
2. После распознавания окно закроется, камера выключится, код появится в нужном поле.
3. Проверить код, заполнить остальные поля и нажать кнопку складской операции.

Сканер не отправляет форму автоматически. Для размещения выбор ячейки остаётся отдельным шагом: скан ячейки заполняет именно поле её штрихкода. Сервер продолжает проверять статус, права, совпадение кодов и вместимость. В выдаче нового поля штрихкода нет — эта операция выполняется после подбора.

Ручной ввод и сканер с вводом как клавиатура сохраняются. Коды хранятся строками, ведущие нули сохраняются. Сканирование принимает непустой код до 80 символов.

## Устройство

- Open source [ZXing Browser](https://github.com/zxing-js/browser), пакет `@zxing/browser` 0.2.1, MIT; многoформатное распознавание в браузере, включая Code 128/39, EAN и QR.
- Иконки [Lucide React](https://lucide.dev/guide/react/) 1.55.0 — для React/Payload Admin. Svelte-клиент продолжает использовать `@lucide/svelte`.
- Декодер загружается по нажатию; видео и распознавание происходят на устройстве, кадры не отправляются на сервер и не сохраняются в S3.
- Запрашивается только видео, с предпочтением задней камеры; нужен HTTPS и разрешение браузера. В локальной разработке localhost также допускает камеру.
- При успехе, закрытии, Escape, переходе со страницы и неудачном запуске поток освобождается. Поздний ответ разрешения после закрытия тоже выключается.
- Есть сообщения для запрета доступа, отсутствующей/занятой камеры, повторная попытка и возврат к ручному вводу.
- Native dialog удерживает фокус; после распознавания фокус возвращается в поле. Стили используют текущую тему Payload.

Код: `backend/src/admin/BarcodeField.tsx`, `WarehousePanel.tsx`, `warehouse.css`. Изменений схемы базы и новых правил складских процессов нет.

## Проверки

Backend: typecheck, unit tests, production build; GitHub CI дополнительно проверяет миграции, интеграционные тесты и весь складской цикл на собранном Docker-образе. Frontend: check, build, test:flows.

В `scripts/camera-smoke.mjs` создаётся видеопоток с настоящими пикселями Code 128; ZXing и его результат не подменяются. `test:live` сканирует вещь в приёмке/размещении/подборе и ячейку в размещении, затем выполняет операции через реальный API. Проверяются отказ разрешения, повтор, Escape, сохранение ручного ввода, позднее разрешение после отмены и отсутствие активных tracks после закрытия. Dialog проверен на мобильном размере 390 × 844.

Физические камеры iPhone/Android ещё не проверены: качество зависит от оптики, фокуса, освещения и качества этикетки. Для складских буквенно-цифровых кодов рекомендуется Code 128. Печать этикеток этим релизом не добавляется.

Версия frontend/backend пакетов — 0.1.2; frontend `release.json` содержит `version` и точный commit. Результаты опубликованного релиза фиксируются в Notion после завершения CI/Coolify и проверки домена. Документы v0.1.1 сохраняются как предыдущая версия.
