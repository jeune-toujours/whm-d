# WHM D · Подход к клиентскому фронтенду

Обновлено: 18 сентября 2026. Статус: клиентский демо-контур для продуктовой проверки до разработки бэкенда.

## Цель и границы

Показать на одном адресе полный клиентский путь: вход и онбординг → «Мои вещи» → сдача или возврат → активный заказ → история, поддержка, профиль и подписка. Все экраны доступны через карту `/#/preview`; можно проверить обычный и пустой сценарии. В этот релиз входят только клиентские интерфейсы. Сотруднические, складские и административные экраны оставлены для отдельного этапа.

Исходная продуктовая структура — [WHM WIKI](https://app.notion.com/p/39475fc615c88093ab0eeea17cc12056), [функциональная структура](https://app.notion.com/p/39475fc615c880bf82abf0143c9b7407), [фирменный стиль](https://app.notion.com/p/3c475fc615c8818fa34fdad364fd7c06). В интерфейсе используется знак пчелы, Open Sans и жёлтая тема WHM.

## Принятые решения

1. **Единое приложение без бэкенда.** Исходные экраны были автономными `.svelte` файлами без проекта и маршрутизации. Добавлены Vite, корневой компонент, общие демо-данные и связь через существующие callback props. Это позволяет позже заменить функции демо-слоя на API-адаптеры без переписывания визуальной структуры.
2. **Hash-маршруты.** Адреса `/#/...` открываются напрямую в статической сборке Vercel и переживают обновление страницы. Панель «Все экраны» и карта `/#/preview` предназначены для ревью и ясно обозначают демо-статус.
3. **Данные только в браузере.** `src/demo.js` задаёт начальные вещи, активный заказ, платежи и обращения. Заказы на сдачу и возврат, изменения профиля и обращения сохраняются в `localStorage`. Переключатель сценария сбрасывает их. Никакие данные не передаются на сервер.
4. **Платежи и документы.** Списание, SMS, курьерский трекинг, документы и отправка обращений имитируются. Форма полного номера карты и CVC удалена из профиля: в будущем карта должна вводиться только у платёжного провайдера; WHM получает маскированный результат. Юридические тексты не выдуманы: пока открывается сообщение о том, что они не утверждены.
5. **Даты и изображения.** Слоты сдачи и возврата рассчитываются относительно текущей даты, чтобы демо не устаревало. Складские фотографии и видео показаны честными пустыми состояниями; для общих иллюстраций добавлены локальные SVG.

## Подключение бэкенда после ревью

1. Утвердить тексты условий хранения, возврата и оферты; правила тарифов и приостановки; форматы ID и статусов заказа.
2. Согласовать схемы API для сессии/OTP, каталога вещей и медиа, заявок, слотов, истории, профиля/подписки, платежей и поддержки. Ввести единые типы `StorageUnit`, `Order`, `Payment`, `Ticket`.
3. Заменить операции в `src/App.svelte` и `src/demo.js` на клиент API с обработкой загрузки/ошибок. Сохранить существующие callback props экранов как границу интеграции.
4. Подключить платёжный редирект/SDK провайдера; не хранить реквизиты карты в приложении. Подключить реальные документы и складские фото/видео после приёмки.
5. Перед публичным запуском заменить демо-доступ реальной авторизацией, убрать карту экранов и верхнюю панель ревью, включить серверные ограничения доступа и наблюдаемость.

## Проверка и публикация

Локально: `npm ci`, `npm run build`, `npm run test:flows`. Браузерная проверка открывает все клиентские маршруты, проверяет отсутствие ошибок JS и горизонтальной прокрутки на 390 px, отсутствие формы банковских реквизитов, а также полные сценарии сдачи и возврата до активного заказа. Для опубликованного URL: `WHM_BASE_URL=https://... npm run test:flows` (в PowerShell задайте переменную через `$env:WHM_BASE_URL=...`).

Vercel использует `vercel.json`: Vite, команда `npm run build`, выходная папка `dist`. Hash-маршрутам не нужен серверный rewrite. Репозиторий должен оставаться приватным; демо-сайт закрыт от индексации `robots.txt` и `noindex`, но любой, у кого есть ссылка, сможет видеть примерные данные.
