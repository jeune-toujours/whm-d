# WHM: повторная сверка и исправление вёрстки

11 октября 2026. Главный эталон — текущие корневые WHM Svelte-файлы, затем продуктовые требования Notion. Master plan определяет техническую архитектуру. Перепроверены восемь карточек клиентских экранов Notion; их содержимое не менялось после предыдущей сверки.

Отчёт в [Notion WHM D](https://app.notion.com/p/3f675fc615c881839d4bd5c3b724b4de).

## Исправления

| Найденная проблема | Исправление |
| --- | --- |
| На карточке вещи и экране подписки кнопка назад сжималась до 38 px; SVG находился выше центра на 3 px | Общая кнопка с Lucide ChevronLeft, размер 44 × 44, без flex shrinking и с точным центрированием; используется на дополнительных экранах |
| Шапки дополнительных экранов и основной контент имели разные max-width и края | Совпадающие контейнеры и отступы на карточке, подписке, платежах, информации и служебных клиентских списках |
| На мобильном возврате следующий шаг был недоступен: desktop actions скрыты до 900 px, мобильная панель существовала только на выборе вещей | Одна нижняя панель на всех четырёх шагах, с теми же обработчиками и блокировками, что на desktop; проверены переходы вперёд и назад |
| Карточка и подтверждение возврата показывали UUID вместо публичного номера вещи; длинные значения нарушали строки | Публичный internalID; перенос длинных значений, несжимаемая copy icon; приватные материалы оформлены как карточки с переносом имени файла |
| Шесть OTP-ячеек на ширине 320 px выходили за границы формы | Ячейки сохраняют архивный вид и уменьшаются по доступной ширине |
| Информационные и fallback экраны всегда были светлыми, live показывал «ДЕМО-КОНТУР» | Текущая тема передаётся во все InfoScreen, live помечается тестовым контуром |
| Связанный заказ в истории мог иметь count без items; при отсутствии его в текущей странице рендер падал | Count fallback для количества и склонения; regression: фильтр «Возврат» → детали → исходная сдача |
| В списке активных заказов показывались фильтры завершённых/отменённых записей, которых в наборе нет | Убраны недействующие фильтры при activeOnly |

Архивные компоновки WHM-6/7/9/11/12/13, темы, типографика и плейсхолдеры сохранены. Исправления внутри корневых экранов устраняют баги без смены дизайна. Backend API, база и тарифные/юридические правила в этом раунде не менялись.

## Проверка

- Frontend check: 0 ошибок, 28 существующих предупреждений.
- Frontend build и `npm run test:flows`; в flows добавлен `scripts/layout-smoke.mjs`, также доступен `npm run test:layout`.
- Layout regression: 274 состояния, обе темы, размеры 320 × 740, 360 × 800, 390 × 844, 768 × 1024, 1024 × 768, 1440 × 900, 844 × 390. Проверяются горизонтальный overflow, размер/центр стрелки, края шапки, сетка контента, переходы wizard и диалоги.
- Live проверка исправленного frontend через staging API: OTP на 320 px; оплата с отказом и повтором в мобильном dialog; карточка реальной тестовой вещи на четырёх ширинах; полный мобильный возврат; приёмка/размещение/подбор/выдача через Payload Admin, приватный S3 и подпись; фильтр истории и переход к связанной сдаче.
- Окончательный выпуск требует зелёного GitHub CI, Coolify finished/healthy, одинакового SHA frontend/backend и повторного browser flow опубликованного домена. Идентификаторы релиза фиксируются в Notion после проверки.

Матрица Chromium не является проверкой на физическом iPhone/Safari или Android. Снимки и временные диагностические scripts остаются локальными, не попадают в Git. Производственные интеграции остаются неподключёнными; SMS и оплата симулируются.
